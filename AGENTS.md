# Fork-local provenance maintenance

This file is a proposed maintenance addition in this fork, not an upstream
product rule. The user explicitly requested separation of requirement origin,
rationale and applicable status, and welcomed PRs as later evidence-review
worksheets. The register layout and procedure below are agent design choices.

For requirement-bearing edits, consult [the provisional register](REQUIREMENT_PROVENANCE.md)
and use [the evidence worksheet](PROVENANCE_REVIEW_TEMPLATE.md) or an equivalent
clear record. Keep inherited text and existing contracts operative unless a
separately supported change replaces them. Do not infer origin from an author
name, imperative wording, repetition, or general permission to continue.

Trace original messages or upstream decisions before tightening an attribution.
Split clauses with different sources, rationale or status. Record specific later
confirmation separately and preserve the original origin. Unknown means not yet
resolved, not "agent-authored", inferior, rejected or newly optional.

This review does not authorize application execution, upstream changes, release,
deployment, synchronization or private-rollout publication. Keep private evidence
out of this public fork and keep session attribution identifier-only. The
worksheet can point to a restricted source without copying its raw contents.
